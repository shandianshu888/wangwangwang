Windows 11 系统代理怎么开：先分清自动、脚本和手动

这篇帮你在 Windows 11 找到系统代理设置，理解三个开关分别干什么，并确认代理是否真的生效。

先给结论如果你使用的客户端带“设置系统代理”开关，通常优先在客户端里启用，让它自动写入系统设置。只有服务明确提供代理地址、端口或脚本地址时，才手动填写 Windows 的对应栏目。

适用对象

适合使用 Windows 11、已经获得合法可用的代理参数，或者正在排查“客户端显示已连接，但浏览器仍走原网络”的读者。本文只解释系统设置，不提供服务地址，也不承诺任何线路效果。

操作前准备

  • 确认代理来源可信，并拿到明确的服务器地址和端口，或 PAC 脚本地址。
  • 记录修改前的开关状态，方便失败时恢复。
  • 关闭不相关的代理软件，避免多个程序来回抢系统设置。

PAC 是 Proxy Auto-Configuration 的缩写，即“代理自动配置脚本”。它会按规则决定哪些请求走代理，而不是把所有地址一股脑塞过去。

环境与版本

本文按 Windows 11 当前的“设置 → 网络和 Internet → 代理”界面整理，创建日期为 2026-10-07。不同系统版本的文字可能略有差异，操作前请确认页面标题仍为“代理”。

分步操作

第一步：打开正确入口

  1. 按 Win + I 打开“设置”。
  2. 选择“网络和 Internet”。
  3. 进入“代理”。你会看到“自动代理设置”和“手动代理设置”。

旺！先别看到三个开关就全开。代理不是自助餐，多夹通常不会更香。

第二步：先判断你拿到的是什么

  • 只有客户端开关：回到客户端，启用“系统代理”或类似选项，不在 Windows 重复填地址。
  • 拿到脚本 URL：在“使用设置脚本”中填入完整地址并保存。
  • 拿到服务器地址和端口：在“使用代理服务器”中填写。地址和端口要分别放进对应输入框。
不要混填脚本地址不是代理服务器地址；像 https://…/proxy.pac 这样的 URL 应放在脚本栏。手动服务器通常由主机名或 IP 加端口组成。

第三步：设置排除项

手动代理区域允许填写“不使用代理服务器”的地址。内网、路由器管理页或明确要求直连的地址可以放这里。多个项目的分隔方式以系统界面提示为准；没有业务需要时，不要随意复制陌生排除列表。

第四步：保存并重开应用

保存后，完全关闭并重新打开需要测试的浏览器或应用。部分程序只在启动时读取系统代理，还有一些程序根本不遵循 Windows 系统代理，这属于应用行为差异，不代表设置一定失败。

成功后的检查方法

  1. 先打开一个已知可正常访问的网站，确认基础网络没有被切断。
  2. 回到代理页面，检查开关和参数是否仍然存在。
  3. 在客户端查看连接日志，确认新请求是否出现。
  4. 如需核对出口地址，请使用你信任的查询站点；不要把查询结果截图连同账号信息公开。

判断成功不能只看客户端按钮变绿。更可靠的证据是：目标应用产生了请求、客户端日志收到连接，并且关闭系统代理后行为发生可解释的变化。

常见错误与解决办法

保存后立刻被改回

通常是另一个客户端仍在管理系统代理。退出其他网络工具，再修改一次；如果公司设备受管理策略控制，请联系管理员，不要尝试绕过策略。

浏览器能用，某个应用不能用

该应用可能不读取系统代理，或只支持特定协议。查看它自己的网络设置和官方文档。别急着给节点判死刑，锅可能还没走到节点那一层。

所有网页都打不开

先关闭“使用代理服务器”或脚本开关，恢复修改前状态。如果网络随即恢复，优先检查地址、端口、脚本可达性和客户端监听状态。

客户端已经退出，系统还保持代理

手动回到 Windows 代理页面关闭对应开关。部分客户端异常退出时来不及恢复设置，属于常见排障点。
